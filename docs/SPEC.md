## 1. 目標與範圍

把原專案的「迷霧探索」成就頁做成**純靜態網站**，部署在 GitHub Pages，讓任何人用自己的照片或 Google 時間軸計算台灣足跡與成就。

**做的**
- 成就頁：探索率（縣市／鄉鎮／村里 × 個數／面積）、迷霧小地圖、每年新解鎖、最近解鎖、明細、成就徽章、成就明細彈窗（含 Leaflet 小地圖）
- 側邊欄改成**成就目錄**（點了跳到對應分類）
- 資料來源轉接層：資料夾照片 EXIF、Google 相簿 Takeout、Google 時間軸（多種格式）

**不做的**
地圖頁、時間軸播放、匯出影片、儀表板、照片牆、編輯頁、縮圖、Synology 連線、任何後端。

## 2. 隱私原則（頁面上要明確寫出）

- **所有計算都在使用者的瀏覽器內完成**，照片、座標、時間不會上傳到任何地方。
- 網站只下載靜態檔（圖資、成就設定），不會送出任何使用者資料。
- **不加任何追蹤、分析或第三方統計**（不使用 Google Analytics 等）。
- 計算結果只存在使用者瀏覽器的 IndexedDB，頁面提供「清除我的資料」按鈕。
- 首頁和匯入畫面都要放顯眼的說明，例如：「🔒 本機運算：你的照片與位置完全掌握在你手中」（2026-11-20 維護者定稿）。
- 外部請求只有兩種：CDN 套件（固定版本）和地圖圖磚。說明頁要列出這兩項，並註明圖磚請求會讓圖磚供應商看到你瀏覽的地圖範圍。

## 3. 計算模式

| | 照片模式 | 造訪模式 |
|---|---|---|
| 使用的資料 | 只有照片（EXIF、Google 相簿 Takeout） | 所有來源合併（照片＋時間軸） |
| 一筆資料代表 | 一張照片 | 一次「造訪紀錄」（時間＋座標） |
| 以張數計算的成就（目前只有「老地方」） | 顯示 | **隱藏** |
| 地圖「制霸五色」（依張數上色，鄉鎮・村里） | 可切換 | **沒有** |
| 預設 | 只匯入照片時 | 有匯入時間軸時（含照片＋時間軸同時匯入） |

- 切換按鈕只在匯入的資料含照片時出現；只有時間軸時固定為造訪模式。
- **統計只看「首次解鎖時間」**：拿掉所有照片數欄位與「依照片數排序」。例外是照片模式下以張數計算的成就與它的明細，以及鄉鎮、村里的張數 `n`（只給「制霸五色」上色，2026-11-21 第二輪加入）。
- **制霸五色**：0 張＝迷霧，1–9 白、10–49 藍、50–99 綠、100–499 橙、500 以上紅；鄉鎮、村里同一組門檻；縣市不提供；預設仍是首次解鎖年份，切換不記憶。顏色在 `js/shared.js` 的 `CONQUER_LEVELS`。
- 判定一律是「任一來源、任一筆紀錄落在範圍內就算解鎖，日期取最早一筆」。

### 和原專案輸出的差異（改寫 `explore_stats.php` 時照此調整）

| 原專案 | 靜態版 |
|---|---|

## 4. 資料來源轉接層

每種來源各寫一個轉接器，輸出統一格式：

```js
// 一筆紀錄
{ lat, lng, time, kind, source }
// time   ：當地時鐘時間當成 UTC 的 unix 秒（沿用原專案規則，見 §5）；不明為 null
// kind   ：'photo' | 'visit' | 'path'（path＝移動途中的點）| 手動紀錄（儲存時 kind 0 照片、1 停留、2 移動途中、3 手動、4 範圍類手動）
// source ：'exif' | 'gphotos' | 'gtimeline' | 'manual'
```

實際儲存時用 TypedArray（`Float64Array` 經緯度、`Int32Array` 時間、`Uint8Array` kind），避免數十萬個物件。

### 4.1 資料夾照片 EXIF

- 選擇方式：`showDirectoryPicker()`（Chrome、Edge，可記住授權）；不支援時改用 `<input type="file" webkitdirectory>`（Firefox、Safari）；也支援直接拖曳資料夾。
- 讀取：`exifr` 只讀檔頭（GPS、`DateTimeOriginal`），支援 JPEG、HEIC、TIFF、各家 RAW 中 exifr 能解析的格式。
- 時間：`DateTimeOriginal` 本身就是當地時鐘時間，直接當 UTC 解讀；沒有時用 `CreateDate`，再沒有就是 null（**不用檔案修改時間**）。
- 沒有 GPS 的照片略過，畫面顯示略過幾張。
- 影片（mp4、mov）第一版不處理。
- 讀取時顯示進度，並且可以中途取消。

**實作（第 4 階段，2026-11-20）**

| 檔案 | 內容 |
|---|---|
| `js/adapters/exif.js` | 取得檔案（`showDirectoryPicker`／`<input webkitdirectory>`／拖曳）、分批交給 Worker、統計略過原因、去除重複 |
| `js/worker/exif.worker.js` | exifr 7.1.3 完整版（jsDelivr `dist/full.esm.mjs`），同時解析 8 個檔，只挑 GPS 與時間欄位、分段讀取（首段 64 KB） |
| `js/store.js` | IndexedDB `fog`／`sources`；不能用時改存記憶體 |

- 支援副檔名：jpg、jpeg、jfif、heic、heif、avif、tif、tiff、dng、cr2、nef、nrw、arw、orf、rw2、pef、srw、raf、png。影片與其他檔案只計數，顯示在略過原因裡。
- 略過的資料夾：名稱以 `.` 或 `@` 開頭（含 Synology 縮圖 `@eaDir`）、`#recycle`、`$RECYCLE.BIN`。
- 時間：`DateTimeOriginal` → `CreateDate` → `DateTimeDigitized`，字串直接當 UTC 解讀。
- 去除重複：座標（6 位小數）與時間都相同的照片只算一筆（同一張照片的多份備份）。
- 來源清單：每個來源顯示有座標筆數、照片張數、台灣範圍內筆數、時間範圍、略過原因（沒有 GPS、重複、無法讀取、影片、其他檔案）、沒有時間的張數；可個別移除或全部清除（都會先確認，只刪瀏覽器裡的匯入結果）。
- 重新開啟頁面時，從 IndexedDB 讀回來源並自動計算，直接顯示成就頁。
- 預設模式：只有照片時用照片模式，有時間軸時用造訪模式；使用者自己切過就不再自動改。

### 4.2 Google 相簿 Takeout

- 照片旁的 JSON 附檔：舊版是 `xxx.jpg.json`，新版是 `xxx.jpg.supplemental-metadata.json`（檔名可能被截斷，以「開頭相同」比對）。
- 座標取 `geoData`（全 0 表示沒有座標，改用 `geoDataExif`）；時間取 `photoTakenTime.timestamp`（UTC 秒，依 §5 轉換）。
- 只讀 JSON，不讀照片本身。附檔沒有座標時，再用照片 EXIF 補（選用）。
- 使用者可以選解壓後的資料夾，或直接選 `.zip`（用 zip.js 只讀需要的 JSON，不整包解壓；第二階段）。

### 4.3 Google 時間軸

依檔案內容自動判斷格式：

| 格式 | 判斷方式 | 停留點（visit） | 移動途中（path） |
|---|---|---|---|
| A. 舊版 Takeout `Records.json` | 有 `locations[]`，元素含 `latitudeE7` | 沒有語意資料 → 用停留偵測產生（見下方） | 所有原始點 |
| B. 舊版 Takeout Semantic Location History（`YYYY_MONTH.json`，可一次選多個檔或整個資料夾） | 有 `timelineObjects[]` | `placeVisit.location`＋`duration.startTimestamp` | `activitySegment` 的起訖點、`waypointPath`、`simplifiedRawPath` |
| C. Android 裝置匯出 `Timeline.json` | 有 `semanticSegments[]` | `visit.topCandidate.placeLocation.latLng`（字串 `"25.03°, 121.56°"`）＋`startTime` | `timelinePath[].point`、`activity.start／end`；另有 `rawSignals` |
| D. iOS 裝置匯出 `location-history.json` | 最外層是陣列，元素有 `startTime`，座標格式為 `"geo:25.03,121.56"` | `visit.topCandidate.placeLocation` | `timelinePath[]`（時間是 `durationMinutesOffsetFromStartTime`）、`activity.start／end` |

- **預設只算停留點**；開關「包含移動途中」打開後才加入 path 點。
- 格式 A 的停留偵測：連續點在 200 公尺內停留 ≥ 10 分鐘，視為一次停留，座標取中心點（參數之後依實測調整）。
- 大檔處理：時間軸檔可能有數百 MB，用 Web Worker 解析，避免頁面卡住。path 點先把座標四捨五入到約 10 公尺並去除重複。
- 有時區偏移的 ISO 時間（`2024-05-01T08:00:00.000+08:00`）：直接取字面上的日期時刻當 UTC，也就是當地時鐘時間。

## 5. 時間規則（沿用原專案 `config/photo_time.php`）

- `time` 是「當地時鐘時間當成 UTC」的 unix 秒；顯示和切日一律用 `getUTC*`。
- 只有 UTC 的來源（Google 相簿 `photoTakenTime`、`Records.json`）：**一律加 8 小時**。成就範圍（台澎金馬、東沙、太平島）全部在 UTC+8，所以不需要依座標推算時區。
- 異常時間（≤ 0、2147483647、超過「現在 + 14 小時」）在統計時視為「時間不明」：仍然算解鎖，但不參與日期判定。
- 「旅行」類成就（單日跨縣市等）以當地日期切日。

## 6. 計算流程（Web Worker）

✅ 第 2 階段完成（2026-11-20）。

```
匯入 → 統一紀錄（TypedArray）→ IndexedDB
     → ① 村里判定：村里外框的格子索引（0.02°）→ 點是否在多邊形內 → villcode；towncode 取村里代碼前 8 碼
     → ② 半徑判定：紀錄的格子索引（0.01°）→ 對山頂、車站、景點等目標查半徑內的紀錄（WGS84 橢球局部距離）
     → ③ 保護區判定：保護區外框的格子索引 → 點是否在多邊形內
     → ④ 彙總：改寫 explore_stats.php 的統計與成就邏輯（依 §3 調整）→ 輸出 stats JSON
     → ⑤ 明細：使用者點開成就時，用 ①～③ 的結果即時計算
```

| 檔案 | 內容 |
|---|---|
| `js/core/geo.js` | TopoJSON 解碼、`PolygonIndex`（點在哪個面內）、`PointIndex`（半徑查詢）、距離、`toGeoJSON` |
| `js/core/compute.js` | `prepareStatic()`（建索引一次）、`compute(records, S, {mode, now})` → `{stats, ctx}`、`detail(ctx, id)` |
| `js/core/data.js` | 載入 `data/`（以 `version.json` 的雜湊當快取參數） |
| `js/worker/compute.worker.js` | module worker：`init`／`compute`／`detail` 訊息 |
| `js/core/client.js` | 主執行緒端 `FogClient`（Promise 包裝；`compute` 會轉移陣列給 Worker） |
| `dev/compare.html` | 開發用比對頁：以原專案照片跑計算，和原專案 API 輸出逐項比對 |

- 空間索引用自寫的格子索引，**不需要 flatbush、kdbush**（少兩個外部套件，Worker 內也不必載 CDN）。
- 台灣範圍外的點在第 ① 步之前就排除（經度 114–124.7、緯度 10–26.5），國外照片不參與任何計算。
- 統計輸出與原專案 `type=stats`、`type=detail` 同格式，去掉照片數；`stats.mode` 標示模式。明細小地圖的範圍外框 `geo.shape` 是 GeoJSON（來自 `shapes.topo.json`，第一次開明細時才載入）。

### 第 2 階段驗證結果（`dev/compare.html`，照片模式）

以原專案 27,559 張照片計算，和原專案 `explore_stats.php` 逐項比對：

- **gzip**：GitHub Pages 傳輸時自動壓縮，瀏覽器自動解壓，不必另外處理。
- 村里界線的頂點本來就稀疏（相鄰頂點距離中位數約 100 m），試過 PostGIS `ST_CoverageSimplify`（1 m）幾乎沒有減少點數，所以不簡化。
- 文字差異：判定條件由「拍照」改成「有足跡」（例如「範圍內有足跡」「車站 250 公尺內有足跡」），因為資料來源不只照片。

### 第 1 階段驗證結果

- **村里判定精度**：用 `villages.topo.json` 判定原專案全部 27,559 張有座標的照片，和資料庫的 villcode（原始界線 ST_Intersects）比對：**27,518 張一致（99.85%）**。41 張不一致全在界線上：約一半 PostGIS 本身就同時判給兩個村里（點正好在共用界線上，原專案只是取了其中一個），其餘離界線 1.4 公尺以內（量化誤差）。

## 14. GitHub Pages 相容性（2026-11-20 確認）

網站執行時**完全不需要 PHP 或任何後端**：用不會執行 PHP 的純靜態伺服器（Python，模擬 GitHub Pages 的子路徑 `/<repo>/` 與 `Cache-Control: max-age=600`）實測，計算、迷霧小地圖、成就明細與範圍外框、明細小地圖圖磚、EXIF Worker（從 jsDelivr 載入 exifr）、IndexedDB、資料夾選擇都正常。

| 項目 | 狀態 |
|---|---|
| 網站檔案 | `index.html`、`css/`、`js/`、`data/` 全是靜態檔，路徑都是相對路徑（放在 `https://<帳號>.github.io/<repo>/` 子路徑可用） |
| PHP | 只有 `tools/` 的維護工具（在維護者電腦執行），網站不會呼叫；放上 Pages 只會被當成文字檔，內容不含帳密 |
| 外部資源 | 只有 OpenStreetMap 圖磚（HTTPS）。Leaflet 1.9.4、exifr 7.1.3 放在 `vendor/`（雜湊值已對過官方 SRI／npm 套件），不從 CDN 載入 |
| CSP | `index.html`、`help.html` 用 `<meta>` 設定：script／connect／worker 只允許 self，img 另允許 data: 與 tile.openstreetmap.org；style 允許 unsafe-inline（innerHTML 裡有 style 屬性）。換圖磚供應商要同步改 CSP |
| HTTPS | Pages 一律 HTTPS，`showDirectoryPicker`、module Worker 都需要安全環境 |
| Jekyll | 加了 `.nojekyll`，讓 Pages 直接提供檔案、不經 Jekyll 處理 |
| 檔案大小 | 最大 `villages.topo.json` 4.6 MB，遠低於 Pages 單檔 100 MB 上限；Pages 會自動 gzip |
| 開發用 | `dev/` 頁面與網址 `?dev` 需要 `test/`（不會上傳），在 Pages 上無法使用，不影響一般使用者 |

**注意事項**

- **同一個帳號的 Pages 共用來源（origin）**：`<帳號>.github.io` 底下所有專案網站共用同一個 IndexedDB、localStorage。匯入的資料（資料庫 `fog`）理論上可被同帳號的其他 Pages 網站讀到。都是自己的網站所以風險低；若要完全隔離，可改用自訂網域。
- **快取**：Pages 的快取時間是 10 分鐘。CSS 與入口 JS 帶版本參數（`?v=日期`），但 ES module 互相 import 的檔案沒有，部署更新後最多 10 分鐘內可能拿到新舊混合的檔案；改版時記得更新 `index.html` 的版本參數。
- **地圖圖磚**：OpenStreetMap 官方圖磚有使用政策（禁止大量使用），使用者多時要換供應商（見 §11 待決事項）。

### 15.1 Google 時間軸

- 維護者的測試檔 `test/Timeline.json` 是 **iOS 匯出格式（§4.3 格式 D）**：5,151 段（停留點 1,584、移動 1,251、路徑 2,316 段共 6,889 點），2025～2026 年，時間帶時區（`+08:00`），座標字串 `geo:緯度,經度`
- 四種格式自動辨識，在 Worker 解析；停留點 kind 1、移動起訖與路徑點 kind 2；頂列加「包含移動途中」開關（預設關）
- 不保存 Google 的地點類型（住家、公司等），只存座標與時間
- **排除可信度太低的停留點**：`visit.probability < 0.3` 不算（維護者的檔案排除 26 / 1,584 筆）。不用 `topCandidate.probability`：那是「停留的是哪個地點」的把握（中位數只有 0.34），成就只需要「到過附近」，用它會誤刪四成
- 驗證：與原專案照片同一天都有紀錄的日子，比對走過的鄉鎮

**實作（2026-11-20）**

| 檔案 | 內容 |
|---|---|
| `js/worker/timeline.worker.js` | 自動辨識四種格式並解析；停留點門檻、路徑點去重複（同一天、約 10 公尺內只留一筆）；A 格式的停留偵測 |
| `js/adapters/gtimeline.js` | 把檔案交給 Worker、錯誤訊息（看不懂的檔案、沒有位置紀錄） |
| `js/app.js` | 時間軸卡片（選檔可多選、拖曳檔案或資料夾）、來源清單摘要、成就目錄的「包含移動途中」開關（記在 localStorage `fog-include-path`，只有造訪模式且有移動途中紀錄時出現） |

- 時間：帶時區偏移的取字面時刻；`Z`（UTC）或沒有時區的加 8 小時。**iOS 匯出的 `timelinePath` 段時間是 `Z`（UTC，以 2 小時為一段），停留點與移動是 `+08:00`**，兩種都要處理
- 測試檔結果：停留點 1,558（排除可信度低 26）、移動途中 6,629 點（去除重複 2,762），台灣範圍內 7,743 筆；65 個停留點帶 `+09:00`（日本），取當地時間；解析 0.24 秒
- 驗證一：Python 依同樣規則獨立解析，停留點數、路徑點數、去重複數、緯度總和、時間總和**完全一致**
- 驗證二（與原專案照片交叉比對）：時間軸有紀錄的日子裡，**91.2%** 的照片所在鄉鎮，時間軸同一天也有到；把時間軸整體挪 ±24 小時降到 26～27%、+8 小時降到 74%，表示日期對齊正確
- 只有時間軸時，頂列不顯示照片／造訪切換（固定造訪模式）

**尚未用真實檔案測過**：Android 匯出（格式 C）、舊版 Takeout 的語意位置記錄（B）與 Records.json（A），依公開的欄位說明實作；有檔案時再驗證

### 15.2 資料備份與轉移（跨裝置，例如存到手機）

- **一般 `.json`，不壓縮**（實測：照片 27,559 筆約 0.9 MB、時間軸 10,975 筆約 0.4 MB，gzip 只省到約 1/4，小型文字檔不必壓縮；不壓縮也方便用文字編輯器檢查）
- 每筆紀錄一行 `[緯度, 經度, 時間, 類型]`（座標 6 位小數；時間為當地時鐘時間當 UTC 的秒數，不明為 null）
- 內容：所有來源（含手動紀錄）＋設定；檔頭有格式名稱與版本號，日後格式改了可以轉換

**更新與去重複（2026-11-20 維護者確認）**

- 每個來源記錄 `added`（加入時間）與 `updated`（最後修改時間），清單上顯示「最後更新」；備份檔一併保存
- 匯入備份以來源 id 判斷是不是同一份資料，再比 `updated`：這裡沒有 → 加入；**備份比較新 → 列出兩邊時間詢問，確定才取代**；相同 → 略過；這裡比較新 → 略過。結束時列出新增、取代、略過的來源與原因
- 重新匯入同類型、同名的來源（例如重新掃描同一個資料夾、再匯入同一個時間軸檔）：詢問「取代舊的」或「另外新增一份」；取代時沿用原本的 id 與加入時間，之後的備份才比得出新舊
- 計算時去掉**座標與時間完全相同**的紀錄（跨來源、同來源都算）：同一份資料匯入兩份時解鎖結果不變，「老地方」張數也不會重複。原專案照片本身有 331 筆完全相同（連拍或重複檔），因此照片模式「老地方」的張數會比原專案少這些
- 限制：同一張照片從資料夾與 Google 相簿 Takeout 各匯入一次時，若 Google 修正過座標，兩筆不完全相同，去不掉（只影響「老地方」張數）
- **手動紀錄逐筆合併（做手動紀錄時實作）**：手動紀錄只有一個來源，每筆有獨立編號；匯入備份時以編號合併，兩台各自新增的都保留。限制（維護者已同意）：在一台刪除的點，匯入到另一台不會跟著刪除
