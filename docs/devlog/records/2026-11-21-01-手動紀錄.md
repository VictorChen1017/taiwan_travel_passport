## 目標

讓使用者把「確實去過、但沒有照片或時間軸」的地點手動加入，並和其他資料一樣參與計算、備份。

## 決定

| 問題 | 決定 | 決定者・理由 |
|---|---|---|
| 只匯入照片的人預設是照片模式，按了看不到效果 | 加入時自動切到造訪模式並提示；有手動紀錄時預設造訪模式 | 維護者（Claude 建議）：保留「照片模式只算照片」的規格 |
| 以範圍判定的地點（國家公園、離島）用代表點，會連帶解鎖一個不一定去過的村里 | 範圍類只解鎖該成就，不解鎖村里（kind 4） | 維護者（Claude 建議）：避免誤解鎖 |
| 刪除單筆的位置 | 明細彈窗中手動那一列的「🗑 刪除」 | 維護者（Claude 建議） |
| 日期 | 可不填；填了存當天 12:00（當地時鐘時間當 UTC） | 規格已定；12:00 為 Claude 實作細節 |

## 做了什麼

- `js/manual.js`（新）：手動紀錄來源（id 固定 `manual`）、items → TypedArray、同地點同日檢查、備份逐筆合併
- `tools/export_static.php`：以範圍判定的 73 個地點加 `rep` 代表點（最大一塊面的 `ST_PointOnSurface`），重新匯出 `achievements.json`
- `js/core/compute.js`：kind 4 不參與村里、半徑、保護區判定，只依 `targets` 解鎖指定地點；明細的手動紀錄各列一行（可刪除）；集點卡明細改為列出全部格子，未到的帶 `add`
- `js/explore.js`：明細彈窗的加入按鈕、行內表單（日期可不填、不可未來）、刪除確認；資料更新後重開同一個明細
- `js/app.js`：加入／刪除、照片模式自動切換、來源清單摘要、匯入備份逐筆合併
- `js/backup.js`：手動紀錄每行多存編號、對象、名稱、加入時間；kind 接受 0～4

## 遇到的問題

- 用 bash heredoc 寫 Python 修補腳本，內容含引號與反引號，bash 解析失敗 → 改用 Edit 工具逐段修改
- Apache 沒開，localhost 打不開 → 改用 Python `http.server` 臨時伺服器（同時也比較接近 GitHub Pages 的純靜態環境）
