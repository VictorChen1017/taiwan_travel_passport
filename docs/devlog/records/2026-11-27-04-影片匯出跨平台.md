# 影片匯出：跨平台踩過的坑與解法（之後做影片分享功能請先讀）

2026-11-27，迷霧地圖播放動畫「🎬 匯出影片」（`js/video.js`、`js/explore.js` 的匯出影片段落）。
同一份程式在 iPhone、Windows 的 Chrome／Edge、內建瀏覽器上出來的影片差很多；以下依踩到的順序整理，最後是給新功能的檢查清單。

## 結論先看

| 項目 | 採用的做法 | 為什麼 |
|---|---|---|
| 格式 | MP4（H.264） | GIF 分享受限、檔案大；WebM 在 iPhone／LINE／IG 支援差 |
| 產生方式 | **WebCodecs 逐格編碼**，不支援才退回 MediaRecorder | 即時錄影會把裝置的卡頓錄進去，每格長短不一 |
| 封裝 | 自己寫的 `Mp4Writer`（約 100 行，不用外部套件） | 原專案用 CDN 的 mp4-muxer；本專案規定第三方放 vendor、CSP 只允許 self，需求簡單就自己寫 |
| 影格率 | 每個時間格只編一張、直接標停留時間（可變影格率），停超過 1 秒每秒補一張 | 畫面是靜止的一格一格；張數約為 30fps 的 1/5，電腦的軟體編碼器才不會慢 |
| 畫質 | 支援就用**固定畫質**（`bitrateMode: 'quantizer'`、QP 18），否則位元率 30 Mbps | 硬體編碼器遇到變化少的畫面不會用滿位元率 |
| 色彩 | **自己把 RGBA 轉成 BT.709 有限範圍的 I420**，MP4 寫 `colr` 標記 | 各家編碼器自己轉的結果不一，沒標記時播放器會解錯 |
| 畫面範圍 | 只框本島（含澎湖、綠島、蘭嶼），金門馬祖不納入 | 電腦畫面寬，全部框進直式影片地圖太小 |
| 分享 | 產生完再按一次「分享／儲存」 | 手機的分享選單要「剛點過按鈕」才能開 |

## 踩到的問題（依順序）

### 1. MediaRecorder 即時錄：每格長短不一、開頭結尾卡頓
- **現象**：iPhone 村里＋全島＋3× 開頭結尾卡一下；Windows 電腦上每一格停的時間長短不一。
- **原因**：MediaRecorder 錄的是「實際經過的時間」。畫一張村里地圖（幾千個區域）要 0.1～0.3 秒，這段時間就變成上一格多停；錄影啟動、停止時也會掉格。分頁在背景時計時器被放慢到每秒一次，會整段錯亂。
- **解法**：改用 WebCodecs，每張 `VideoFrame` 自己標 `timestamp`、`duration`，和畫圖花多久完全無關，也不用等實際時間。MediaRecorder 只留給不支援 WebCodecs 的瀏覽器，換格時間對準整條時間軸（前一格畫太久下一格就少停），總長度至少是對的。

### 2. 產生時畫面上的地圖跟著動，看起來像在錄影
- **原因**：第一版每格都呼叫 `goFrame`，彈窗裡的地圖一格一格走。
- **解法**：只畫在不在畫面上的 canvas；每格的上色用 `fillsAt(i)` 算好，暫時借給繪圖函式，畫完還原。進度改成「第 k / N 格、已花 X 秒」（和原專案時間軸匯出一樣）。

### 3. 電腦的 H.264 編碼器比手機慢很多
- **現象**：內建瀏覽器（Chromium，軟體編碼）每秒只能編約 22 張 1080×1920。
- **解法**：每個時間格只編一張，直接標它停多久（MP4 的 `stts` 記每張長度）；805 張降到 146 張。關鍵格至少每 2 秒一個。
- **注意**：送進編碼器的 `framerate` 要給**實際的平均影格率**，不能照 30 給，否則每張分到的資料量只剩 1/5。

### 4. 檔案很小、細線糊掉（Windows 硬體編碼器）
- **現象**：設 10 Mbps、30 Mbps 都一樣，8.8 秒只有 180 KB，關鍵格 15 KB。
- **原因**：硬體編碼器的位元率是「上限」概念，畫面變化少時自己省下來，畫質就掉了。
- **解法**：`VideoEncoder.isConfigSupported` 先試 `bitrateMode: 'quantizer'`，支援就每張 `encode(frame, { avc: { quantizer: 18 } })` 固定畫質；不支援（Safari）才用位元率。結果：電腦約 600 KB、iPhone 約 1.9 MB，維護者確認達標。

### 5. 顏色偏青、偏淡（Windows）
- **現象**：淡藍底色（219,236,255）播出來變成（241,255,255）。
- **原因**：把 canvas 直接交給編碼器時，有的編碼器輸出**全範圍**（0～255）的 YUV，卻沒在檔案裡標記；播放器預設當成**有限範圍**（16～235）來解讀，顏色被拉亮。用 ffmpeg 以兩種範圍解碼比對才確定。
- **解法**：自己把 RGBA 轉成 BT.709 有限範圍的 I420（`rgbaToI420`，整數運算，1080×1920 一張約 20～40 毫秒），用 `new VideoFrame(buffer, { format: 'I420', colorSpace })` 交給編碼器；MP4 的 avc1 裡加 `colr`（nclx：1／1／1、有限範圍）。驗證：解出來是（217,235,255），和網頁一致。

### 6. H.264 level 與硬體編碼器
- 直式 1080×1920 剛好在 level 4.0 上限；30 Mbps 超過 level 4.0 的 25 Mbps。有些電腦的硬體編碼器不接受某些尺寸或 level。
- **解法**：依序試 High 4.2、5.0、5.1、4.0、Main 4.2、Baseline 4.2；**開始產生前再用實際輸出尺寸（直式或方形）檢查一次**，不行才退回 MediaRecorder。

### 7. 分頁在背景、等待編碼器
- `setTimeout` 在背景分頁會被放慢到每秒一次 → 讓出執行緒用 `MessageChannel`；等編碼器消化用 `dequeue` 事件（另加 100 毫秒保險，編碼器出錯時不會發事件）。

### 8. 手機分享
- `navigator.share` 要有「剛點過按鈕」的使用者動作；影片做完時已經過了好幾秒 → 完成後顯示「📤 分享／儲存」讓使用者再按一次。不能分享時用 `<a download>` 下載。

## 怎麼驗證（測試瀏覽器看不到影片時）

- 內建瀏覽器擋 blob 影片播放（CSP 沒有 media-src，也有自己的安全檢查），看不到成品。
- 做法：開發伺服器的 `POST /__save?path=img/__vtest.png`（只收 img/ 底下的 .png／.webp，暫借來存影片），存好後複製到 scratchpad，測完丟資源回收筒。
- 本機有 ffmpeg：`C:\Program Files (x86)\ffmpeg-7.1-essentials_build\bin\`
  - 結構：`ffprobe -show_entries stream=codec_name,profile,level,width,height,nb_frames,duration,color_range,color_space`
  - 每張長度：`ffprobe -select_streams v -show_entries packet=pts_time,duration_time,flags -of csv=p=0`
  - 每張大小（關鍵格 K）：`-show_entries packet=size,flags`
  - 整段解碼：`ffmpeg -i x.mp4 -f null -`（可變影格率時會出現「non monotonically increasing dts」警告，是 null 輸出猜成固定影格率造成，時間戳本身正確即可）
  - 顏色：`-vf "crop=4:4:X:Y,scale=in_color_matrix=bt709:in_range=tv,format=rgb24" -f rawvideo -` 和網頁色比對
  - 抽畫面：`-sseof -0.3 -frames:v 1`，再 `crop`＋`scale=...:flags=neighbor` 放大看細線
- 錄影途中要看畫面：攔截 `HTMLCanvasElement.prototype.captureStream` 取得錄製用 canvas 再 `toDataURL`（MediaRecorder 時）。
- 開發用測試資料（`?dev` 的「載入原專案測試資料」）不會保存，**重新整理後要重新載入**，否則成就頁是空的。

## 之後做影片分享功能的檢查清單

1. 用 `js/video.js` 的 `videoSupport()`／`makeVideo()`，只要提供 `draw(ctx, i)` 和 `holdMs(i)`；不要自己再用 MediaRecorder 錄畫面
2. 畫在不在畫面上的 canvas，不要動使用者看到的畫面；按鈕、拉桿不能出現在影片裡
3. 尺寸用偶數；先用實際尺寸 `videoSupport(W, H)` 檢查
4. 靜止為主的畫面用「一格一張＋停留時間」；真的有連續動態（例如路線慢慢畫出來）才用固定 30fps，並把位元率／畫質重新評估
5. 顏色一律走 `rgbaToI420`＋`colr`，不要把 canvas 直接交給編碼器
6. 完成後讓使用者再按一次分享；檔名用中文＋日期
7. 驗收：iPhone、Windows Chrome／Edge、Mac 各產生一次，用 ffprobe 看時間、大小、顏色，並在手機上實際分享到 LINE／IG
