# 界線更新：讓相鄰的邊完全重合（2026-11-26）

這份紀錄說明村里、鄉鎮界線怎麼從「舊的簡化檔、相鄰界線對不上」換成「不留縫的簡化」。commit：`5925eb6`（迷霧地圖的海岸線另見 `1a05e96`）。內容依 `docs/SPEC.md` §7 與 `tools/export_static.php` 整理；換圖資的工作在前一個對話完成。

## 問題：相鄰的兩個村里，邊對不上

迷霧地圖和成就判定都靠界線：地圖要畫出每個村里，判定要知道照片落在哪個村里。舊的界線有兩個問題：

- **來源本身就是簡化過的檔案**（Big5 編碼，約 37 萬點），而且約 89 個村里名稱裡的罕用字變成了「?」。
- **每個區域各自簡化**。簡化就是把線上不重要的點去掉，讓檔案變小。可是兩個相鄰村里共用的那條邊，在 A 村算一次、在 B 村又算一次，兩邊去掉的點不一樣，結果原本同一條線變成兩條不重合的線。地圖上就會出現**細縫**（露出底色）或**重疊**；判定時，剛好落在縫裡的照片不屬於任何村里，落在重疊處的又可能被算到兩邊。

## 做法一：換成未簡化的原始界線，先整理乾淨

- 改用內政部未簡化的原檔：村里 `VILLAGE_NLSC_1150407`（約 204 萬點）、鄉鎮 `TOWN_MOI_1140318`；縣市界不變。名稱的罕用字也一起修好了。
- 原檔本身也不完美，相鄰區域之間可能有極細的縫或小重疊。匯入本機資料庫時先用 PostGIS 的 `ST_CoverageClean` 把整層整理成「不留縫」的狀態：寬度小於約 50 公尺的細縫併給隔壁區域，重疊的部分切開分給其中一邊。整理後，每條相鄰的邊在兩個區域裡是**同一串點**。
- 原本的資料表備份為 `backup.villages_20261126`、`backup.towns_20261126`，可以隨時比對或還原。
- 屏東縣瑪家鄉三和村是另外附的檔案，和長治、內埔、鹽埔重疊，不納入。

## 做法二：整層一起簡化，共用的邊只簡化一次

原檔太細，不能直接放到網頁上，還是要簡化。關鍵是改用 `ST_CoverageSimplify`（PostGIS 3.6／GEOS 3.14 以上）：它把**整層區域當成一張拼圖一起處理**，先找出哪些邊是兩個區域共用的，每條共用的邊只簡化一次，兩邊用同一個結果。所以簡化完，相鄰的邊依然完全重合，不會產生新的縫或重疊。

這套做法用在兩個地方，容許值依用途不同：

| 用途 | 檔案 | 簡化程度 |
|---|---|---|
| 判定照片在哪個村里 | `villages.topo.json` | 約 10 公尺（0.0001 度），再量化到約 1.1 公尺 |
| 迷霧地圖（畫圖） | `map_county／town／village.json` | 縣市 0.004、鄉鎮 0.002、村里 0.0018 度 |

迷霧地圖另外兩個細節：

- **縣市層的來源不一致**：大部分縣市用縣市界，但金門、連江縣市界缺少，改用鄉鎮合併。兩種來源拼起來的邊對不上，所以縣市層在匯出時再做一次 `ST_CoverageClean` 對齊，然後才簡化。
- **小碎塊怎麼丟**：每個區域保留最大的一塊，以及面積大於 2e-6 的小塊；更小的塊只有在「沒有和其他區域相接」時才丟（例如離島旁的沙洲）。如果和鄰居相接的小塊也丟掉，陸地上就會破一個洞。

## 結果

- 地圖上相鄰區域之間不再有細縫或重疊，放大看也是密合的（後來排查 iPhone 破圖時，單獨畫出旗山區一帶確認過，見 [迷霧地圖手機效能](2026-11-26-02-迷霧地圖手機效能.md)）。
- 判定用的村里檔反而變小：4,552 KB → 4,388 KB（gzip 1,497 → 1,370 KB）。迷霧地圖因為原檔細節更多而變大：縣市 34 → 52 KB、鄉鎮 210 → 334 KB、村里 1,343 → 1,809 KB。
- 用原專案照片測試，村里解鎖數 1287 → 1289：邊界附近 11 個新進、9 個移出，都是照片剛好在界線附近、新舊界線位置不同造成的；自動檢查的基準跟著更新。
- 因為邊完全重合，後來可以用 `ST_CoverageUnion` 把同一層的所有區域合併成一條**海岸線**，加粗畫在迷霧地圖最上層，而且和每個區域的邊完全對齊（`1a05e96`）。

## 之後更新界線的步驟

1. 取得新的內政部原檔，匯入本機 `photo_monitor` 資料庫，匯入時用 `ST_CoverageClean` 整理（先備份原表）
2. 執行 `C:/xampp/php/php.exe tools/export_static.php units maps villages`（只下 SELECT），必要時加 `achievements`
3. 開 `dev/selftest.html` 跑自動檢查；村里解鎖數若因界線位置改變而變動，確認變動的村里都在界線附近後，再更新 `dev/selftest.js` 的基準
4. 更新 `docs/SPEC.md` §7 的檔案大小與來源說明
