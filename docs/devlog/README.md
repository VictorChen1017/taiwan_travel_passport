# 開發日誌

維護者說「寫開發日誌」時寫一份**階段性報表**：統整這段時間做了哪些功能、克服了哪些難題、對話過程的檢討。給人快速看懂進度用，**一頁以內**（約 30～50 行），細節留在 `records/`。

## 檔名

`YYYY-MM-DD-NN.md`：日期＋當天第幾份（從 01 起）。

## 格式

```markdown
# 開發日誌 YYYY-MM-DD 第 N 份

期間：上一份日誌之後 ～ 現在｜commit：`起`～`迄`（未 commit 的註明）

## 完成的功能
- 功能名稱：一句話說明用途（不列檔案）

## 克服的難題
- 問題 → 怎麼解決（一行一個，只列真正卡住或值得記住的）

## 對話檢討
- 做得好的：……
- 要改進的：……（等待、來回次數、token、溝通）
- 下次的做法：……

## 下一步
- 依優先順序，最多 3～5 項
```

## 寫法

- 繁體中文；寫給維護者看，用功能與結果描述，不寫程式細節
- 沒有實際驗證的事要寫明，不寫成已完成
- 想保留逐筆細節（每次 commit 的決定、驗證數字）時，另外放在 `records/`，檔名 `YYYY-MM-DD-NN-主題.md`
